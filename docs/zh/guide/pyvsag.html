VSAG文档

pyvsag

pyvsag 是 VSAG 官方的 Python 绑定，是一个纯 Python 层，通过 cffi 调用 C API（libvsag_c）。每个 CPU 架构只需一个 py3-none 平台 wheel，即可适用于所有 CPython 3.10+ 版本。数据仅以指针、形状和 dtype 的形式跨越边界，因此不依赖 NumPy 的 ABI。源代码位于 python/。

安装

pip install pyvsag

要求：

  • 平台： Linux x86_64 或 aarch64，glibc 2.28 及以上（manylinux_2_28，例如 Ubuntu 20.04+、 Debian 10+、RHEL/Alma/Rocky 8+）。正式 PyPI 暂无 macOS、Windows 以及 Alpine 等基于 musl 的发行版 wheel；macOS arm64 可通过下文的 TestPyPI 工作流获取，也可在本机构建。
  • Python： CPython 3.10 及以上。支持 3.10 到 3.14；wheel 不依赖 Python ABI，更新的版本无需新的 wheel。
  • 依赖： numpy 和 cffi，会自动安装。wheel 自带 OpenMP 运行时，不依赖 libaio、libcurl 和 OpenBLAS。

每晚构建（TestPyPI）

pyvsag TestPyPI 工作流会在每晚和手动触发时，用 main 构建 wheel 并发布到 TestPyPI（上传可暂停）。 覆盖 Linux x86_64/aarch64 和 macOS Apple Silicon arm64（macosx_15_0_arm64）。 版本号带 .devN，需要加 --pre；依赖仍从正式 PyPI 安装：

pip install numpy cffi
pip install --pre --no-deps --index-url https://test.pypi.org/simple/ pyvsag

macOS 作业执行 make pyvsag 和 Mach-O 审计，然后在干净环境中安装同一个经 SHA-256 校验的 wheel： CPython 3.10–3.14 搭配 NumPy 2.x，CPython 3.10–3.12 额外覆盖 NumPy 1.26.4。 两个 Python 3.12 作业分别搭配 NumPy 1.26.4 和 2.x，强制安装 torch==2.15.0、scikit-learn==1.9.1， 以 KMP_DUPLICATE_LIB_OK=FALSE 运行全部六种 OpenMP 导入顺序；缺少依赖或跳过 OpenMP 测试均视为失败。 最低支持 macOS 15，与 CI 的运行系统版本一致。最低版本已从 macOS 14 提高到 15； macOS 14 不再属于支持范围，本地默认源码构建同样以 15.0 为目标。

Linux 与 macOS 独立上传；只有 macOS 上传等待 macOS 矩阵全部通过。上传后，新的 macOS 作业仅从 TestPyPI 下载精确版本 （不下载依赖、不使用 pip 缓存），对照构建清单校验文件名和 SHA-256，再审计并在干净环境中运行普通测试集。 下载最多重试十分钟，等待索引更新。如果 TestPyPI 已有同名 macOS 文件，上传前会明确报错； 应在原上传运行中仅重跑验证作业，或使用新版本。依赖单独从正式 PyPI 安装。 手动运行时取消勾选 publish，可验证任意分支，只保留构建和测试产物，不上传也不执行发布后验证。 工作流产物保留源码 SHA、wheel 哈希、依赖版本和测试报告。正式 PyPI 发布流程仍只包含 Linux。

从源码构建

make pyvsag
pip install wheelhouse/pyvsag-*.whl

make pyvsag 在仓库根目录运行 scripts/python/local_build_wheel.sh，并把 wheel 写入 wheelhouse/。 在 Linux 上，有 Docker 时在 manylinux_2_28 镜像中构建，并在镜像内运行 tests/python 的一部分用例； 没有 Docker 时使用 python -m build 构建原生 linux_<arch> wheel，安装到当前虚拟环境并运行 tests/python。 如果当前不在虚拟环境中，脚本会在仓库内创建 .venv/。

在 macOS Apple Silicon 上，先安装 Xcode Command Line Tools 和 Homebrew，再运行：

bash scripts/deps/install_deps_macos.sh
# 激活 Python 3.10+ 虚拟环境，或确保 PATH 中的 python3 为 3.10+。
make pyvsag

macOS 始终原生构建，即使 Docker 正在运行。构建要求 CMake 3.20+ 和 PATH 中的 Perl（可用 perl -v 检查，缺少时运行 brew install perl），静态链接 OpenBLAS 和 LLVM OpenMP 20.1.8， 仅导出 VSAG C API，以隔离其他包的 OpenMP 运行时。固定版本的 OpenMP 源码会自动下载并编译， 仅 macOS wheel 包含其 Apache-2.0-with-LLVM-exception 许可证及归属声明。 源码构建需要访问 GitHub Release 下载地址，或通过 VSAG_THIRDPARTY_OPENMP_20_1_8 和 VSAG_THIRDPARTY_LLVM_CMAKE_20_1_8 配置镜像 URL，分别提供未修改的 openmp-20.1.8.src.tar.xz 和 cmake-20.1.8.src.tar.xz；镜像文件仍须通过 SHA256 校验。OpenMP 子构建使用与 VSAG 相同的 CMAKE_BUILD_PARALLEL_LEVEL 并发上限。 构建会自动安装 delocate，修复动态依赖并检查本机架构；随后运行 Mach-O 审计，要求唯一原生库为 libvsag_c.dylib、仅依赖系统库、仅导出 C API、包含许可证元数据，并且部署目标不高于 wheel 标签，最后安装并运行测试。

默认 MACOSX_DEPLOYMENT_TARGET 为 15.0，统一应用于 VSAG 及从源码构建的依赖；默认构建无需设置环境变量。 如需调整部署目标，可设置 MACOSX_DEPLOYMENT_TARGET；如需限制编译并发，可设置 CMAKE_BUILD_PARALLEL_LEVEL。 macosx_15_0_arm64 标签声明最低支持 macOS 15，CI 也在此系统版本上运行。 TestPyPI 包含 macOS arm64，正式 PyPI 发布仍只包含 Linux。在测试环境中安装 torch 和 scikit-learn 可同时运行可选的 OpenMP 共存测试。

macOS wheel 构建启用 VSAG_OPENMP_STATIC，普通 C++ 构建仍使用动态 OpenMP。 C++ 构建可通过 Homebrew 安装 libomp，或向 CMake 传入 -DLIBOMP_PREFIX=/path/to/libomp。 wheel 构建可通过可选的 LIBOMP_PREFIX 环境变量指定包含 $LIBOMP_PREFIX/include/omp.h 和 $LIBOMP_PREFIX/lib/libomp.a 的自定义安装； 静态库的最低系统要求不能高于部署目标。构建会拒绝要求较新系统的 Homebrew 库，而不会仅修改标签。 取消 LIBOMP_PREFIX 即恢复使用兼容部署目标的源码构建。

如果想直接使用源码树中的构建结果，而不打包 wheel：

make debug VSAG_ENABLE_PYBINDS=ON              # 生成 build/src/libvsag_c.so
bash scripts/python/prepare_python_build.sh    # 生成 python/pyvsag/_version.py
export PYVSAG_LIBRARY="$PWD/build/src/libvsag_c.so"
export PYTHONPATH="$PWD/python"

macOS 上将 build/src/libvsag_c.so 替换为 build/src/libvsag_c.dylib。

PYVSAG_LIBRARY 指定要加载的 libvsag_c；未设置时，pyvsag 加载与 Python 文件放在一起的那一份。

快速开始

pyvsag.Index(name, parameters) 接受索引名称和 JSON 字符串形式的参数，与 C++ 的 vsag::Factory::CreateIndex 签名对应：

import json
import numpy as np
import pyvsag

dim = 128
num_elements = 10_000

data = np.random.random((num_elements, dim)).astype(np.float32)
ids = np.arange(num_elements, dtype=np.int64)

index_params = json.dumps({
    "dtype": "float32",
    "metric_type": "l2",
    "dim": dim,
    "index_param": {
        "base_quantization_type": "fp32",
        "max_degree": 32,
        "ef_construction": 300,
    },
})

index = pyvsag.Index("hgraph", index_params)
index.build(vectors=data, ids=ids, num_elements=num_elements, dim=dim)

query = np.random.random(dim).astype(np.float32)
search_params = json.dumps({"hgraph": {"ef_search": 100}})
result_ids, result_dists = index.knn_search(
    vector=query, k=10, parameters=search_params,
)
for rid, rdist in zip(result_ids, result_dists):
    print(f"{rid}: {rdist}")

可用的索引类型和参数请参考 创建索引 和 索引参数。完整示例位于仓库的 examples/python/ 目录，建议从 103_index_hgraph.py 开始。

数据类型与输入规则

索引 dtype传给 build、add 和各搜索方法的向量
float32numpy.float32
float16numpy.float16
bfloat16包含 bfloat16 原始位模式的 numpy.uint16 数组
sparseCSR 数组：index_pointers（uint32）、indices（uint32）、values（float32）

pyvsag 不会转换或复制稠密向量，以保持零拷贝；不匹配的输入会以 ValueError 拒绝：

  • 稠密数组的 dtype 必须与上表完全一致，使用本机字节序，并且是 C 连续的（二维矩阵必须是行优先，且每行长度等于 dim）；
  • ID 数组以及稀疏的 index_pointers、indices 必须是整数数组，数值要落在目标类型（int64、uint32）范围内； 浮点 ID 和越界数值会被拒绝，而不是被截断；
  • build 和 add 的 ids 必须是一维数组，每个向量对应一个元素。

搜索

方法返回值
knn_search(vector, k, parameters)(ids, distances)：形状为 (k,) 的数组（int64、float32）。搜索未能填满的位置为 -1。
knn_search(index_pointers, indices, values, k, parameters)稀疏查询批次的同样结果，形状为 (num_queries, k)。
range_search(point, threshold, parameters)threshold 范围内所有结果的 (ids, distances)；没有结果时为空数组。
knn_search_with_statistics(...) / range_search_with_statistics(...)上述数组，外加 JSON 字符串形式的搜索统计信息（稀疏批次为字符串列表）。见 搜索统计。

参数可以按位置或按关键字传递（vector=、k=、parameters=、point=、threshold=）。

稀疏向量

稀疏向量使用 CSR 布局：第 i 行拥有 indices[index_pointers[i]:index_pointers[i + 1]] 及对应的 values；index_pointers 从 0 开始且不递减。

index = pyvsag.Index("sindi", json.dumps({
    "dtype": "sparse",
    "dim": 128,
    "metric_type": "ip",
    "index_param": {"use_reorder": True, "doc_prune_ratio": 0.0, "window_size": 50000},
}))
index.build(index_pointers=ptrs, indices=cols, values=vals, ids=ids)
index.add(ptrs, cols, vals, new_ids)
result_ids, result_dists = index.knn_search(
    q_ptrs, q_cols, q_vals, 10, json.dumps({"sindi": {"n_candidate": 100}}),
)

pyvsag.sparse 还提供稀疏 HDF5 基准数据布局的解码，见 数据集格式。

保存与加载

index.save("index.bin")

new_index = pyvsag.Index("hgraph", index_params)
new_index.load("index.bin")

底层序列化或反序列化失败（包括文件无法打开）时，save 与 load 会抛出 RuntimeError。

索引操作

方法返回值说明
build(...)None稠密 build(vectors, ids, num_elements, dim) 或稀疏 build(index_pointers, indices, values, ids)。
add(...)None与 build 相同的两种形式。
remove(ids)int删除一维整数 ID 数组，返回实际删除的数量。没有 ID 被删除和操作失败时都返回 0。
get_num_elements()int索引当前元素数量。
get_memory_usage()int索引占用的内存字节数。
check_id_exist(id)bool指定 ID 当前是否存在。
get_min_max_id()(min_id, max_id)操作失败时返回 (-1, -1)。
calc_distances_by_id(query, ids)（旧别名 cal_distance_by_id）numpy.ndarray每个 ID 一个 float32 距离，缺失 ID 为 -1。
 
# 添加两条稠密向量
new_vectors = np.random.random((2, dim)).astype(np.float32)
new_ids = np.array([10_001, 10_002], dtype=np.int64)
index.add(new_vectors, new_ids, len(new_ids), dim)

assert index.check_id_exist(10_001)
print(index.get_num_elements(), index.get_memory_usage())
print(index.get_min_max_id())

# 计算一个 query 到候选 ID 列表的距离
candidate_ids = np.array([10_001, 10_002], dtype=np.int64)
distances = index.calc_distances_by_id(query, candidate_ids)

# 删除 ID；返回值为实际删除数量
removed = index.remove(candidate_ids)

add 接受展开的连续数组或行优先的二维矩阵。具体操作是否受支持仍取决于索引类型。

calc_distances_by_id 接受一个一维 float32 query（长度等于索引维度）和一个一维 ID 数组。长度不对的 query 和空 query 会以 RuntimeError 拒绝，不会被当作缺失 ID。其他 NumPy 输入会按需转为连续的 float32 / int64 数组，正负步长的视图都保持逻辑顺序。它不支持稀疏、多向量或多 query 输入。

错误处理

失败情形行为
pyvsag.Index(...) 无法创建索引RuntimeError（error type: UNSUPPORTED_INDEX、error type: invalid_parameter 或 error type: unexpectedError）
build、add、save、load、get_num_elements、get_memory_usage、check_id_exist、calc_distances_by_id、*_with_statisticsRuntimeError，消息以操作名开头并附带 C++ 错误信息
knn_search不抛异常：ids 和 distances 都填 -1
range_search不抛异常：返回空数组
remove不抛异常：返回 0
get_min_max_id不抛异常：返回 (-1, -1)
dtype、形状、布局、字节序或整数范围不对ValueError；调用参数不对时抛出 TypeError

如果搜索失败时必须抛出异常，请使用 *_with_statistics 变体。

日志

pyvsag.set_logger_off()     # 关闭库的日志输出
pyvsag.set_logger_info()    # 仅输出重要信息
pyvsag.set_logger_debug()   # 输出详细调试信息

pyvsag.__version__ 为包的版本号。

线程与进程

  • 每次调用 C++ 库时都会释放 GIL，库内部的 OpenMP 线程不受 GIL 影响，线程数可通过 OMP_NUM_THREADS 控制。 支持多个 Python 线程并发搜索；其他并发操作遵循 C++ 索引的规则。
  • pyvsag 可以与 PyTorch、scikit-learn 等其他 OpenMP 使用者共存于同一进程； tests/python/test_openmp_coexistence.py 覆盖了所有导入顺序。
  • 使用 multiprocessing 时请选择 spawn 启动方式，不要在 fork 之间共享索引。
  • 对 copy.copy(index) 得到的浅拷贝与原对象共享同一个原生索引；最后一个引用消失时才释放原生索引。

与 C++ 库的关系

pyvsag 封装的是同一份 vsag::Index 实现，并与 C++ 共享底层索引二进制，因此行为和性能特征一致。 只要参数匹配，就可以在 Python 中构建索引、在 C++ 中加载（反之亦然）。大多数 C++ 参数在 Python 中以相同的 JSON 字段传递；C++ 新增的索引类型、量化方式和距离度量会随 pyvsag 的下一个 release 发布。

发布的 wheel 使用 ENABLE_LIBAIO=OFF 构建，因此不依赖 libaio。async_io 仍可选用，但会退化为带缓冲的 兼容后端（单次 buffer_io 读取，且写入后不做 fsync），并只打印一次警告；需要真正的 libaio 路径时，请在本地用 VSAG_ENABLE_LIBAIO=ON pip install python/ 自行构建。详见磁盘索引。

Node.js 对应接口

Node.js 的 calcDistancesById(query, ids) 和旧别名 calDistanceById(query, ids) 返回一维 Float32Array。query 必须为 Float32Array，ID 必须为 BigInt64Array，其他数组类型抛出 TypeError； 实际 query 长度通过 C++ Dataset API 校验，底层操作失败时抛出包含 C++ 信息的 Error。缺失 ID 仍返回 -1，不属于操作失败。
